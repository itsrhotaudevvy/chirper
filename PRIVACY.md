# Privacy

Chirper is an on-device messenger with no server of its own. This document lists what Chirper
stores, where it is stored, and what leaves your device. It describes the design; if the code
disagrees with this document, that is a bug and we want to hear about it.

## Summary

- Chirper has **no account with us** and **no server**. There is nothing to sign up for.
- **No telemetry, no analytics, no crash reporting.** Chirper does not phone home.
- **No remote fonts, CDNs or third-party web resources.** Fonts ship inside the app.
- The **only outbound traffic** is to the messaging networks you log in to, through their own
  protocols, as a client of that network would.
- Keys and tokens are kept in the **OS keystore**, not in plain files.

## What is stored, and where

All data lives in the app's private data directory on your device. Nothing is copied anywhere else
by Chirper.

| Data | Where | Protection |
|---|---|---|
| Chats, messages, contacts, read state | Local database in the app data directory | Encrypted at rest with SQLCipher where the build includes it, with a 32-byte key |
| Database key | OS keystore: macOS Keychain, Windows Credential Manager, Linux Secret Service, Android Keystore (wraps the key with AES-GCM), iOS Keychain (`ThisDeviceOnly`) | Never written to a file, never logged |
| Media (images, video, voice, files) | Local media vault in the app data directory | Encrypted with AES-GCM |
| Network login sessions and tokens | Local store, with the connector state | Stored under the same key as the database; never logged |
| App settings (theme, notification privacy, lock timeout) | Local settings in the app data directory | Not secret |
| App lock state | Derived from your OS biometrics or passphrase | Biometric data never leaves the OS |

File permissions on desktop and Linux are `0700` for directories and `0600` for files.

## What leaves your device

Only traffic to the networks you have logged in to. For example, if you add WhatsApp, Chirper talks to
WhatsApp's servers, exactly as the official client would. Chirper sends:

- messages, reactions, read receipts and typing indicators that you send, to the chat you choose,
- the connection traffic those networks need to keep your session alive and deliver messages,
- media you attach, to that network.

The networks see your traffic as usual. What they do with it is governed by their own privacy
policies. Chirper does not change that, and it cannot reduce the metadata a network already sees.

Chirper does **not** send:

- analytics or usage events,
- crash reports or diagnostic dumps,
- message content, contacts or keys to any server operated by the Chirper project,
- anything to advertising or tracking services.

Opening a link inside a chat uses the system browser only after you tap it.

## Logs

Chirper logs operational events (connect, disconnect, errors by category). Logs never contain message
bodies, tokens, cookies, phone numbers or keys. If you share a log with a bug report, check it for
personal identifiers first.

## Notifications

Notifications are generated by the operating system on your device. Chirper can hide message content
in notifications (a setting). Notification content is not sent through any Chirper service, because there
is none.

## Deleting your data

- **Log out of a network** in the app to remove its session and stored tokens.
- **Uninstall the app** to remove the app and its data directory, as your operating system does for
  any app. Chirper does not keep a copy elsewhere.
- Keystore entries may outlive an uninstall on some platforms. If you want the key gone as well, check
  the keystore settings of your OS after uninstalling.

Deleting messages on a network is done through that network, not through Chirper.
